## Leads worth chasing

1. **moon v2.0 toolchain roster is the highest-value unresolved question.** The only maintainer statement I have on moon's polyglot tiering is from 2024-09-04; v2.0 (2026-05) replaced the toolchain system with WASM plugins. Next round should read moonrepo.dev's current toolchain/plugin index directly and answer: does moon v2 ship first-party Python, Go, and Elixir toolchains, and does content hashing/caching work for them? If yes, moon becomes the leading candidate for this decision; if no, it collapses to "task runner with a nice config."
2. **Contradiction to resolve:** secondary sources repeatedly describe moon as "polyglot by design" and "the sleeper pick for polyglot repos (Node.js + Rust + Go)" while the maintainer's own words say Python/Go get no integration beyond PATH execution. That is marketing register vs. primary source — the primary wins until v2 docs say otherwise.
3. **Aspect Build / Alex Eagle "Hidden Cost of Bazel" podcast** (aviator.co) — an ex-Bazel-team engineer discussing why Bazel costs what it costs. Best single lead for Q3 (setup + ongoing maintenance cost) and it is a practitioner rather than vendor register.
4. **`elixir-workspace`** is a new entity worth its own look — if the Elixir project stays on Mix-native tooling, the "partial monorepo" option (merge only the JS cluster) gets much stronger, because the Elixir side would keep its own toolchain regardless of layout.
5. **Bazel 9.x + bzlmod migration burden** — Bazel 9 forces a bzlmod refactor (bazelbuild/bazel discussion #28344). For a solo dev this is a recurring tax worth quantifying; a major-version migration cost is exactly the kind of thing that kills solo adoption.
6. **Nx "lazy graph hydration"** — if it ships, it directly removes the "install every language's toolchain to compute the graph" tax. Worth checking whether it landed in any Nx release after 2026-02.

## Looked for and could NOT find

- **Current version numbers for Buck2, Please, and Rush.** Buck2 has no stable version surfaced in search at all (only "open-sourced 2023"); Please and Rush did not appear in any result this run. For a solo-dev decision, Buck2's lack of a discoverable stable release line is itself a signal.
- **Any evidence of Elixir/Mix support in Nx, Turborepo, moon, or Pants.** Not "weak support" — *absent*. Pants' documented backend list excludes it, Nx's roadmap never names it, Turborepo is JS/TS by tagline, and the only moon statement predates v2. There is no open-source Bazel Elixir ruleset either. This is a strong, consistent negative finding across four independent tool ecosystems.
- **Any evidence of Solidity/Foundry/Hardhat as a first-class citizen in ANY monorepo orchestrator.** Only existence-proof repos, no first-party plugin from any of the eight tools.
- **Measured CI fan-out numbers in a polyglot monorepo** — no source with real figures for affected-detection false-positive rate, GitHub Actions matrix cost, or wasted-minutes analysis. The Nx lockfile conservatism is the only concrete mechanism I could name, and I could not date it against a current version.
- **Verified quantified cost from the Kubernetes Bazel→Make downgrade.** The paper exists and is credible (McIntosh's group), but I did not extract confirmable figures; the numbers relayed to me read as generic and I refuse to cite them as measured.
- **Post-mortems of teams abandoning Pants or Buck2 specifically.** Only Bazel has a documented abandonment case. One case study is an anecdote by the two-source rule — the Bazel-cost claim is currently supported by one paper plus one practitioner podcast I did not read.
- **Cross-language remote caching evidence.** Pants' docs mention "shared result caching" and "concurrent and remote execution" generally, but no source this run demonstrated that caching works across a Go + Python + Elixir + Node mix in practice, as opposed to per-backend.
