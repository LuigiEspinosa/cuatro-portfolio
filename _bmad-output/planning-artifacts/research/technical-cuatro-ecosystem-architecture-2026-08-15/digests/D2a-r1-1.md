## The ceiling — what tokens alone DO and DO NOT get you

**Blunt caveat:** I did **not** find honest first-hand retrospectives quantifying token-only coherence
this run. The split below is inference from the structural evidence I *did* retrieve (what these
systems chose to ship, and where they chose to spend engineering), not from organisations reporting
their own outcomes. Treat it as a hypothesis to test in round 2, not as an evidenced finding.

**Holds with tokens alone (high confidence, low risk):**
- Color, including semantic roles and light/dark theming — this is the canonical token payload;
  Material 3 documents design tokens as the foundation layer (https://m3.material.io/foundations/design-tokens).
- Type scale, spacing scale, radii, elevation, motion durations/easings — all pure value layers with
  no behaviour attached, expressible as CSS custom properties consumed identically by all six stacks.
- Salesforce's documented choice is the strongest structural signal here: per a secondary summary,
  Lightning ships **design token packages per platform rather than component implementations via a
  multi-platform framework** (dbanks.design, search-snippet level — *not verified against Salesforce
  primary sources this run*).

**Drifts without shared components (asserted, needs evidence):**
- Form controls — because behaviour, not just appearance, must match: focus rings, invalid states,
  keyboard handling, label association. Web components additionally hit **form participation** across
  the shadow boundary (ElementInternals), which I did not verify current status on.
- Focus/keyboard interaction states generally — tokens carry the *color* of a focus ring, not *when*
  it appears.
- Dense data UI: tables, date pickers, comboboxes, modals/overlays (focus trap, scroll lock,
  z-index/portal strategy). This is exactly the surface where React Aria/React Spectrum's value
  lives — Adobe justifying a React-native implementation on "API decisions made with React's
  lifecycle and context in mind" is a statement that *behavioural* components do not federate cleanly.

**The honest ceiling statement I can defend today:** tokens federate everything that is a *value*.
Nothing retrieved this run shows tokens federating anything that is a *behaviour*. The six-framework
question therefore reduces to: how much of your suite's perceived coherence is value versus behaviour.

## Direct read on the decision (stated as judgement, flagged as such)

Evidence-backed portion: every multi-vendor precedent I actually verified (Adobe, Carbon, and by
withdrawal Material Web) lands on **web-component core + per-framework wrappers + community ports**,
and none of them achieves one component consumed natively by all frameworks. Adobe, with far more
resources than a solo developer, pays for two full implementations *and* a wrapper layer and states
no plan to consolidate. Google tried the single-WC-library answer and defunded it.

Judgement portion (not evidenced, my read): for a solo developer, tokens are the only layer that
federates across all six at acceptable cost, with web components as a *selective* second layer for
a small number of high-value, low-behaviour surfaces — and Phoenix LiveView's SSR requirement is the
hardest constraint in the set, because DSD support is exactly where React 19 still fails.

## Leads worth chasing

1. **Read the React 19 DSD story properly.** https://sordyl.dev/blog/react-19-support-for-web-components/ and the Stackademic DSD-in-React piece. Need a second independent source before treating "React 19 SSR + DSD is broken" as settled — this is a two-source-class claim and currently has one.
2. **Declarative Shadow DOM browser support matrix, 2026.** I never verified it. Check caniuse/MDN/BCD directly plus one browser-vendor post. This is the load-bearing fact for whether WC + Phoenix LiveView SSR is even possible.
3. **Salesforce Lightning primary sources** — verify the "tokens per platform, not shared components" claim against Salesforce's own docs/repos rather than a third-party blog.
4. **GitHub Primer** is the highest-value unchecked precedent for this specific decision: it ships *both* `@primer/react` and `primer/view_components` (Rails ViewComponent, server-rendered) off a shared CSS/token layer. That is the closest published analogue to "JS frameworks + server-rendered stack, one visual system". Go straight to both repos.
5. **Porsche Design System `/packages` directory + docs site** — the repo landing page disclosed nothing. The packages list will show the wrapper-per-framework pattern concretely, plus SSR docs.
6. **Nord's repo, not its marketing page** — underlying WC library, SSR posture, wrapper packages, commit cadence, contributor count.
7. **Form participation across shadow DOM (ElementInternals) current status** — the classic 2021-2023 complaint. Verify whether it is fixed in 2026 before repeating it.
8. **Carbon FAQ + `@carbon/web-components` repo** — confirm the "community-supported Angular/Vue/Svelte" claim from IBM's own words, and check the community ports' commit recency for drift evidence.
9. **LiveView + web components** — the Freshcode article 403'd. Find an accessible account (Dashbit blog, Phoenix forum, ElixirConf talks) of LiveView's DOM patching interacting with custom elements and `phx-update="ignore"`.

## Looked for and could NOT find

- **Any published number** for the effort multiplier of maintaining one component across 3+ frameworks. The search surface is entirely vendor marketing. Reported as thin.
- **Honest first-hand retrospectives** on where token-only consistency breaks down. I found no post-mortem-register account, only prescriptive "tokens are great" content. The "holds vs drifts" split above is therefore inference, and I have marked it so.
- **Verified data for 9 of the 13 named systems** (Lightning, Fluent, Polaris, Primer, SAP, Atlassian, USWDS, Porsche detail, Scale). Rows left empty rather than filled from memory.
- **Maintainer headcounts** for any system. Not published on the surfaces I read; would need repo contributor graphs over time.
- **Declarative Shadow DOM browser support status in 2026** — never retrieved. Significant gap.
- **Any published precedent of Phoenix LiveView consuming a shared cross-framework token or component layer.** The one candidate article was 403-blocked. This remains completely open and is the highest-risk unknown in the whole dimension.
