## Intent

**Problem:** The two applications inside the Anchor consume the token contract two ways: `apps/tournament` loads
`contracts/` directly (Story 8.6), while `apps/tracker` carries a vendored copy under `apps/tracker/app/cuatro-contracts/`
(Story 8.5), which `apps/hub/app/__tests__/anchor-contract.test.ts` admits through `VENDORED_IN_APPS`. The Operator ruled
R24 on 2026-10-17 (`ops/restyle-floor.md`): option (a), `token_contract` stays absent for an `absorbed_into:
cuatro-portfolio` entry, and both applications read `contracts/` directly.

**Approach:** Delete the vendored folder, point `apps/tracker/app/global.css` at `../../../contracts/tailwind.css`, copy
`contracts/` into the tracker image's builder stage as the tournament's Dockerfile does, tighten the Anchor test back to
no `cuatro-contracts/` anywhere in the repository, and retarget the tracker's own floor test at `contracts/`. Close DW-358
and DW-361, and date the change under R24.

**Acceptance Criteria:**
- Given the repository, when `git ls-files` is listed, then no path has a `cuatro-contracts` segment and
  `anchor-contract.test.ts` admits none (no `VENDORED_IN_APPS`).
- Given `apps/tracker/app/global.css`, when its first `@import` is read, then it is `../../../contracts/tailwind.css`, and
  `tailwindcss` is not imported a second time.
- Given the tracker built before and after, when the emitted CSS is compared, then it is identical apart from the hashed
  font file names, and the three contract faces are emitted with the same bytes.
- Given `apps/tracker/Dockerfile` built from the repository root, when the image builds, then its CSS carries the same
  `--token-*` roles and `@font-face` faces as the local build.
- Given the tracker's `typecheck`, `test` and `build`, and the root suite, when run, then all pass.
- Given `deferred-work.md` and `ops/restyle-floor.md`, when read, then DW-358 and DW-361 are `done` and R24 carries a dated
  line naming the commit.

**Boundaries:** presentation, microcopy, DOM and behaviour unchanged; no Registry release; `contracts/` untouched; no push.

**Surprise: the Tailwind version the adapter resolves.** `@import "tailwindcss"` resolves from the file that holds
it. The vendored adapter sat in `apps/tracker/` and got the tracker's `tailwindcss` 4.2.2; `contracts/tailwind.css`
resolves the root `tailwindcss` 4.3.3 (the Hub's devDependency) for preflight and the default theme. The utilities
are still generated by the tracker's `@tailwindcss/postcss` 4.2.2. The measured result: the main stylesheet differs in
exactly two preflight rules, both inert in the tracker: the `html` fallback font stack inside
`var(--default-font-family, ...)`, which is never used because the contract defines `--default-font-family:
var(--f-body)`, and `:-moz-focusring` becoming `:-moz-focusring:where(:not(iframe))`, while the tracker renders no
`<iframe>` (grep over `apps/tracker` `*.ts`/`*.tsx`). No computed style changes on any element the tracker renders.
Aligning the two versions is a dependency change, so it is filed as DW-362 rather than done here.
