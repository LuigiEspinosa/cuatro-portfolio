## What Went Well (and why — keep doing this)

1. **Proportionate scope discipline.** Every migration story explicitly refused to copy the forward-looking `SOLUTION-DESIGN` illustration blocks verbatim (they reference tables that do not exist yet). No forward FK to a non-existent table (`final_match_id`, `target_match_id`, `ceremony.snapshot_id` all deferred). This is the single biggest reason every `db reset` stayed green.
2. **Compounding "Previous story intelligence."** Each story fed the next. The grant lesson from 1.3 arrived in 1.4 as a refined convention, not a re-discovery. Knowledge moved forward instead of being re-learned.
3. **Verify by running, not reasoning.** The grant probe (1.3) and the trailing-newline regex refutation (1.2) both came from executing against a real Postgres cluster rather than trusting a doc or a reviewer's Perl-ism.
4. **Test discipline scaled cleanly.** 30 → 78 → 120 assertions, always green, always regression-checked, with explicit `plan(N)` accounting after the 1.3 mis-count.

## Key Insights / Breakthroughs

- **The always-revoked Data-API default (Story 1.3).** The Dev Notes assumed Supabase auto-grants DML to `anon`/`authenticated`; it does not — those roles had zero privileges. Caught empirically before shipping and turned into the grant convention every migration now follows: each migration adds its own explicit GRANTs, or roles `42501`.
- **Append-only lives at the grant layer, not policy absence (Story 1.4).** `service_role` has BYPASSRLS, so "no UPDATE/DELETE policy" alone would not bind the writer. Granting `SELECT, INSERT` only (no UPDATE/DELETE) is the real teeth behind AD-17.
- **Refuting a claimed HIGH with evidence (Story 1.2).** A trailing-newline regex-bypass claim was empirically disproven against a live PostgreSQL 18.4 cluster (`$` is end-of-string, not newline-anchored). Established the "test the claim, don't trust the framing" habit.
- **Dormant admin-read policy pattern.** Admin-only tables (`app_role`, `audit_log`, snapshot tables) get an `is_admin()` SELECT policy kept as documented defense-in-depth; admins read via server routes with the service key, not the client Data API.

## What Was Hard (minor, systems-level)

- **A deferred outward action rode along for three stories.** The remote `db push` dangled across 1.2 → 1.3 → 1.4 before landing in 1.4. Resolved fine, but a loose end persisted longer than ideal.
- **`granted_by` invariant bounced homes:** 1.2 → "1.3" → finally Story 2.4. Now correctly tracked; it is the first inherited item of Epic 2.
- **`plan(N)` mis-count** cost a review cycle in 1.3, fixed by explicit assertion accounting in 1.4. Keep the habit.
