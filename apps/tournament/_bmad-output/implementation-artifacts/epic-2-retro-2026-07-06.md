## What Went Well (keep doing this)

1. **Review earned its keep on security.** 2.1's first cut shipped a critical identity-spoof — `body.set` (last-wins) on the `check_authentication` re-POST vs `params.get` (first-wins) on the ID extraction, letting anyone with a valid assertion auth as *any* SteamID64, including a future admin. Caught by the adversarial layer, fixed with regression tests, never ran live. The single most important catch of the epic.
2. **One named central decision per story, resolved before dev.** 2.2 "write both stores," 2.3 "AC6 in scope," 2.4 "Option A instant-revoke," 2.5 "five decisions" — each surfaced to and resolved by the Project Lead up front. Proof it works: 2.5, the heaviest story, produced **zero** review patches.
3. **Architecture invariants became code.** AD-12 revoke made *literally instant* (Option-A authoritative re-read); AD-7 two-policy RLS read *realized for the first time* in `roster_entry`; AD-4 canonical key *locked by a pgTAP catalog guard* that bites every future table; AD-8 `requireAdmin` gate primitive *established* for Epic 4 to consume.
4. **Compounding intelligence.** Seams and patterns moved forward instead of being re-learned: `HttpPost` (2.1) → `HttpGetJson` (2.3); `requireAdmin` (2.4) → `requireUser` (2.5); the `app_role`-first read (2.2) is *why* revoke sticks in 2.4.
5. **Test discipline scaled cleanly.** 0 → 104 Vitest, 120 → 171 pgTAP, always green, always regression-checked, with explicit `plan(N)` accounting held every time.

## Key Insights / Breakthroughs

- **Option A = authoritative re-read for instant revoke (2.4).** Supabase access tokens are stateless JWTs, and there is *no* admin "sign this user out by id" (`signOut` needs the live token). Making "a stale JWT can't retain admin" *literally* true required a cheap per-request `app_role` PK SELECT. Live-proven: revoke → instant 403 before refresh.
- **`app_role`-first read makes revoke durable (2.2).** Reading the table before the allowlist means a revoked admin is never re-promoted on re-login even if still in `ADMIN_STEAMIDS`. One ordering decision; load-bearing through 2.4.
- **The Admin API replaces `app_metadata`, it does not deep-merge (2.2, reused 2.4).** Every `updateUserById` must pass *both* `{steamid64, role}` or it wipes the other claim. The most-reused gotcha of the epic.
- **The live-QA gate is irreducible for version-sensitive external behavior.** Supabase Auth's session-mint semantics (2.1 `verifyOtp` type, 2.2 backfill-lands-in-first-JWT, 2.4 instant-revoke timing) could not be proven headlessly — only a real Steam login settled them. This is *why* Epic 2 felt a notch harder than pure-SQL Epic 1.
- **Adversarial review over-flags; verification does the real work.** Every story's review actively *killed* false-premise findings (2.4 alone killed 3 high-severity false premises — a "dead" constant that was in fact used, an "unreachable" FK path, a "critical" CSRF non-exploitable under `SameSite=Lax` + a JSON-body requirement). Triage/verify is not a rubber stamp.

## What Was Hard (minor, systems-level)

- **Version-sensitive Supabase Auth, unprovable in CI.** The recurring friction — not rework, but "the tool behaves in a way you can only confirm live," which made live-QA a hard gate on every story.
- **`server-only` breaks Vitest.** `import 'server-only'` throws under plain Node — *why 2.1 never unit-tested `session.ts`*. Fixed with a stub + alias in 2.2, then reused by every later story.
- **Design research for 2.4.** Confirming there is no by-id `signOut` (against the installed `@supabase/auth-js` 2.110.0) is what forced the whole Option-A design — real investigation, not a lookup.
- **Fail-closed subtleties recurred in review** (2.1 missing try/catch, 2.2 silent-skip-then-mint, 2.4 must-throw-not-pretend-heal, 2.5 audit-fail→500). Now codified as the "don't-swallow" discipline.
